# Set up this agent toolbox

1. **Inventory the machine.** Read [README.md](README.md) and check the OS, Git, Python 3.9+, the repo status, and the config folders in `HARNESSES`. Ask the user for the toolbox name and which agent to start with. Have them handle interactive sign-in and open the agent once if its folder is missing. Use `python3` if needed.
2. **Personalize the source.** Set the agreed name in [toolbox.json](toolbox.json) before the first sync and update the README heading. Rename the checkout folder if the user wants that and it can be moved safely from outside the current workspace. Keep the toolbox name stable after install. Help the user write instructions that reflect how they work. Add a machine label and tags in [machines.json](machines.json) only if they want routing. Keep credentials and local identifiers out of committed files.
3. **Preview the exact install.** Run `python squad.py sync --dry-run`, adding `--as <label>` if using machine routing. Compare detected agents with the intended ones. Resolve missing config folders and review reported backups or duplicates with the user before applying a change that would replace their existing skill. Edit this repo as the source of truth. Preserve unrelated work and leave Git reset, force-push, or stashing out of onboarding.
4. **Apply and verify.** Run the same command without `--dry-run`. Check the intended skill folders and marked blocks, confirm `sync.json` records the intended revision or `null` for an uncommitted starter, and rerun the dry run for `0 change(s)`. Ask the user to open a fresh agent session and confirm a starter skill is visible if you cannot see a fresh session yourself. Report any unexpected agent or unresolved duplicate.
5. **Extend only if requested.** Confirm before creating a remote, publishing, or enabling a background job. Use the README's second-machine steps. Check the configured upstream and a clean checkout first. Verify the revision and a new successful scheduled run in `sync.json` and `sync.log`. For multiple machines, report the verified revision or actual blocker for each. Report offline or unlinked machines as unverified.

End with the machine and agent checked, the sync result, and anything the user still needs to do.
